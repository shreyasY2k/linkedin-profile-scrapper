- (event) Brain dump captured: assignment to reverse-engineer LinkedIn APIs and ship a hosted HTTPS API taking a profile URL, returning structured JSON (name, headline, location, about, experience, education, skills, certs, languages, images). Own LinkedIn creds allowed in backend.
- (decision) Stakes read: graded take-home assignment, hard 2-day deadline (due ~2026-08-29). User calls it 'a simple project' -> right-size the brief tight, no investor-grade rigor.
- (decision) Deployment constraint fixed by user: Oracle Cloud free tier, exposed via Cloudflare, DNS shreyaskaushik.dpdns.org. Not up for debate - treat as given.
- (event) Hard deliverables from assignment spec: public GitHub repo with full source, README covering setup + API docs + approach + known limitations, secrets kept out of repo, public HTTPS endpoint. Reference example: PhantomBuster LinkedIn Profile Scraper.
- (decision) Working mode: Coaching path chosen by user despite 2-day clock. Keep coaching sharp but brisk - time is the binding constraint.
- (decision) Fetch strategy: Voyager internal API (li_at cookie) as primary, Playwright headless-browser fallback when Voyager fails. Two paths to build.
- (decision) Stack: Python + FastAPI. Rationale: user fluency + auto OpenAPI docs satisfies README API-documentation deliverable.
- (change) SCOPE EXPANSION by user: API is public but gated by Keycloak auth with Google SSO; user has IAM creds. Goes beyond assignment spec (which asks for no auth). Flagged for time-risk review; grader-access path must be resolved.
- (assumption) OPEN FORK: unclear whether each authenticated user supplies their own LinkedIn session, or Keycloak merely gates access to a single owner-held LinkedIn account. Materially changes architecture + legal story. Asked user.
- (decision) RESOLVED FORK: per-user BYO LinkedIn session. After Google SSO via Keycloak, each user supplies their own li_at cookie, stored encrypted per-user and keyed to their Keycloak subject. Supersedes the single-backend-account assumption.
- (decision) Grader lane: Keycloak service account using OAuth2 client_credentials grant. Two curl commands documented in README, no browser redirect. Grader must never be blocked by a browser SSO flow.
- (decision) Keycloak experience confirmed: user has configured realms/clients/IdPs before. Keycloak treated as hours not days - no longer arguing for a simpler gate.
- (event) TOP RISK IDENTIFIED: no Oracle instance provisioned yet. Chosen design (Keycloak JVM + Playwright Chromium + FastAPI) does not fit Always Free AMD micro at 1GB RAM; it effectively requires the ARM Ampere A1 shape, whose free-tier capacity is frequently exhausted ('Out of host capacity'). Infrastructure, not code, is the critical path.
- (assumption) Per-user cookie vault implies encryption at rest (e.g. Fernet key from env, never in repo) - satisfies the assignment's 'keep all credentials and secrets out of the repository' requirement and becomes a README talking point.
- (override) User reaffirmed Oracle-only hosting after being shown the ARM capacity risk and the no-Oracle-requirement-in-spec argument. ACCEPTED SINGLE POINT OF FAILURE on the critical path - user's explicit decision, documented not re-litigated. Mitigations offered: request 1 OCPU/6GB instead of 4/24, scripted OCI CLI retry across all ADs, optional PAYG upgrade for capacity priority.
- (decision) Cut-line ACCEPTED as proposed. MUST: FastAPI + Voyager client + full field extraction + public HTTPS + Keycloak client_credentials grader lane + encrypted per-user cookie vault + cache-with-stale-serve + README + public repo. SHOULD: Google SSO federation, rate limiting. COULD: Playwright fallback (demoted from primary plan). WONT: bulk/batch, company pages, search, posts, UI.
- (decision) Cache-with-stale-serve elevated above Playwright fallback as the primary resilience story: every successful fetch cached, served with stale:true flag when live Voyager call fails. Directly mitigates the grader-hits-dead-endpoint failure mode.
- (change) User added requirement: environment parity. Must run locally as well as on Oracle - all config via env vars in a swappable env file per environment. Promoted to MUST. Implies twelve-factor config, .env.example committed with dummy values, real .env gitignored, docker-compose for local parity. Also satisfies the assignment's secrets-out-of-repo requirement and supplies README setup instructions.
- (change) Source docs reconciled with spec after infra resolution: Oracle capacity risk marked RESOLVED (instance running), TLS-termination and Oracle host-firewall risks added, deployment topology added to Solution and to addendum Technical Constraints, day-1 plan reworked around a walking-skeleton deploy, session-overwrite and unbounded-cache decisions recorded.
